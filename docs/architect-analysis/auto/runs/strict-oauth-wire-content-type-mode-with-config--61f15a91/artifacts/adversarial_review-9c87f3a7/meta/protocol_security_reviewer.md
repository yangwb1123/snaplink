Fetched RFC 9126 §2.1 verbatim: PAR body MUST be `x-www-form-urlencoded` (UTF-8), and 415 is not in the RFC 6749 §5.2 vocabulary — 400 `invalid_request` is the only RFC-consistent rejection.

**2. No distinguishability strict vs permissive — PASS.** Structural property: strict mode changes outcomes only for requests permissive **accepts**. The only divergences are inherent mode detection (valid JSON) and the RAR caveat.

Design's strict-only binding is the only coherent fix; pins: P1 (RawMessage case on a **strict-only** form path, never shared `setFormField` — else permissive form byte-compat breaks), P2 (malformed RAR in strict form → bind-level 400, byte-identical to permissive JSON-mode outcome).
