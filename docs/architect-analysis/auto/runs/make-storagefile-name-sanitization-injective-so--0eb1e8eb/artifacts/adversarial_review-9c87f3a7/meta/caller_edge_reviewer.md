## Verification results

**1. `snapshotcmd list` per-row `Get` (main.go:100-110) — graceful per-row error, never abort/crash.** The loop prints `<name>  ?  ?  ?  (get error: <err>)` and `continue`s, per its documented "a single bad file doesn't hide the rest" intent. Key finding: for **F4 legacy files it never misses at all** — `List` returns the sanitized spelling `a_b` (decode identity for allowlist names) and `Get("a_b")` hits. For F5 foreign `a%zz.snap`, `List` returns literal `a%zz`, `Get` misses, and the row is flagged with `(get error: snapshot: not found)` while all other rows render. Nuance: flagged rows still exit 0 (pre-existing behavior).

**2. gRPC admin `List` paging (admin_snapshots.go:96-121) — duplicate decoded names cannot break cursoring.** Verified `decodeOffset`/`pageBounds`/`encodeOffset` (admin_paginate.go:116-157): paging is pure index math over a fully materialized sorted slice — **no name-based cursor**. Duplicates (`a%2f.snap` + `a%2Fb.snap` → `"a/b"` twice) are adjacent equal strings; cursor arithmetic, termination (`""` at `hi >= total`), and `TotalSize` are all unaffected. Each duplicate row renders the canonical envelope. The only failure — a row whose `Get` misses entirely — fails the **whole page** with `codes.NotFound` (not per-row, unlike snapshotcmd), but that is a **pre-existing class**: today's code fails identically for the same file (sanitize miss → `ErrSnapshotNotFound`). No panic, no new page-failure class.

**3. retention `PruneOldest` (retention.go:42-68) — no data loss, no unbounded loop; one pre-existing phantom-report artifact.** The `snap_` filter means the design's own F5 duplicates (`a%zz`, `a/b`) are never victims. For a `snap_`-prefixed foreign twin (`snap_a%2fb.snap` vs canonical `snap_a%2Fb.snap`): `Delete(decoded)` deterministically removes **only the canonical file**; the foreign twin's bytes are never addressed by any op → **no data loss**. Within a run: single pass over a victims slice computed once (`ctx.Done` per iteration), duplicate entries merely double-report — no retry/loop. Across runs: the survivor re-lists, `Get` misses → classified "deletable" (retention.go:31-36) → idempotent delete → re-reported as pruned every tick (phantom report; bounded per run, no crash). This exact artifact exists in today's code for any unaddressable `snap_*` file — the change neither introduces nor widens it.

**4. `snapshotcmd inspect`/`verify` on legacy names (F4) — deterministic non-crashing miss.** `--id a/b` → `sso-ctl snapshot: get "a/b": snapshot not found`, exit 1, before any peek/decrypt. `--id a_b` (sanitized spelling) hits and works fully. Inherent ambiguity (a legit `a_b` colliding) is the documented no-migration rationale.
