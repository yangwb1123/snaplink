**(1) Oracle consistency — ACCEPT.** All three miss classes (genuine, F4 legacy, F5 foreign) converge on the identical branch in `Get` (`file.go:96-101`): encode → Join → `os.ReadFile` → ENOENT → the single `errors.New` sentinel returned **unwrapped**. The F2 too-long guard error is a pure function of the name → also oracle-free. Micro-pin: state in §4 that the sentinel is returned unwrapped, and assert exact equality (not just `errors.Is`) on one F4/F5 row.

**(2) TOCTOU/symlink/dir-precreation — ACCEPT.** Verified against Go 1.26.5 source: `CreateTemp` is `O_CREATE|O_EXCL` with a ≤10-digit random suffix and 10,000 retries (temp name can't be pre-created or symlink-guessed); `rename(2)` replaces a destination symlink without following it; a pre-created dir at the target fails EISDIR → the pinned `rename:` backstop, no partial state; tmp+target share baseDir → same-FS atomic rename; encoded names contain no `/` → traversal structurally impossible. A foreign file created between List and Get/Delete **cannot redirect writes**: Put/Get/Delete only ever open the canonical spelling; any other spelling is never touched. Residual surfaces (Get follows symlinks, List→Get read TOCTOU) are pre-existing, require 0o700 baseDir write access, and sealed envelopes fail Load on tamper — recommend one threat-model sentence in §4.

**(3) F5 name confusion / case-insensitivity — ACCEPT on Linux surface, 2 concrete deltas.** On ext4/xfs/btrfs/overlayfs (the deployment surface: Linux containers) `a%2Fb` vs `a%2fb` are distinct files; the duplicate-row/Delete-canonical-only semantics hold as pinned, and the foreign twin becomes a phantom row whose Get misses consistently (§1). New observation: retention re-reports the phantom "deleted" every pass (idempotent nil) — false-positive, no data loss, document in F5. On case-insensitive FS (macOS/Windows dev) the design's semantics *break* (Get would hit the foreign file) and legitimate `A/B` vs `a/b` collide — but that's out of the deployment surface. Deltas: (a) one doc sentence pinning the case-sensitive-FS assumption; (b) a case-sensitivity probe + `t.Skip` in `ForeignBarePercent`, because the lowercase-hex row as committed **fails silently on a CI-FS checkout**.

**(4) F4 sanitized-spelling readability — ACCEPT, no leak.** `a_b` is the legacy file's *original* name: identical bytes, permissions (0o600/0o700), and authorization surface before and after upgrade. No new name, no new enumeration path, no byte copy. The only surface change is a *loss* (`Get("a/b")` now misses); removing a read path cannot leak. New `Put("a/b")` writes `a%2Fb.snap` and never clobbers `a_b.snap` (pinned).
