# Mutation-style review: R1/R2/R3 detection mechanisms vs the 14-row failure-mode table

I verified each mechanism against the actual repo code (helpers, consts, wiring) and, where useful, mutated the inputs mentally and traced the runtime behavior. Working-tree note first, because it changes one premise:

**Tree state.** `docs/openapi.yaml` already carries the step-1 purge in the working tree (`git diff` = exactly the 2 deleted lines; 0 `8080` hits; mtime during my review — the tree is being migrated concurrently). None of the three test files exist yet. All line-number evidence in the design (E1's 55–56, E4's 142–159, E9's 136) matched HEAD at design time and still matches modulo the purge.

## Row-by-row verdicts

**Row 1 — R1 field equality (suffix drift). CONFIRMED, non-vacuous.** `buildBaseMetadata` sets the five fields unconditionally from `base` (`server_discovery_config.go:142-149`); JSON keys confirmed in `protocols/oidc/metadata.go` (`authorization_endpoint`, `token_endpoint`, `jwks_uri`, `revocation_endpoint`, `introspection_endpoint`). Any re-advertised `/authenticate` endpoint yields `got = server.URL+"/authenticate" ≠ server.URL+core.PathLogin` → per-field `t.Errorf` fires. `editionServer` sets `cfg.Issuer = "https://issuer.example"`, which is why the design correctly excludes the `issuer` field (§7); the five endpoints stay request-derived, so no interference.

**Row 2 — R1 raw-body `bytes.Contains`. CONFIRMED, and it is the *only* detector for non-asserted fields.** Concrete non-vacuous case: `check_session_iframe` is emitted for minimal/standard (`sessionManagementEnabled` is true unconditionally at `app.go:82`) and deliberately unasserted (C2) — a mutation redirecting it to `/authenticate` is invisible to row 1 but caught here. **Over-broad flag:** the pattern is the unquoted substring (same shape as `assertNoLegacyPathPort`), so any legitimate future advertised field containing `/authenticate` — e.g. a real `op_policy_uri`/`op_tos_uri` URL (`applyStaticClaimsAndSecurity`) or a new endpoint field — fails. Low risk, consistent with repo precedent; state it in the test comment.

**Row 3 — R1 `net/url` port checks. CONFIRMED with two caveats.** (a) The `8080:0` double-colon shape does **not** parse: I ran `url.Parse("http://localhost:8080:0/auth/login")` and Go returns `invalid port ":8080:0" after host`. The "parse + string compare" mechanism only fails if the parse-error branch is coded as `t.Fatalf` — pin that explicitly; it's currently implied. (b) Detection power is fully **subsumed by row 1**: the port is part of the compared full URL, so any port mutation already fails equality. The port check's real value is the named-failure diagnostic (which acceptance case 3's message contract requires) plus the `8080`/`0` explicit classes. Not vacuous, but redundant — worth stating honestly in the design. (c) `requestBaseURL` = `middleware.BaseURL` = `"http://" + r.Host` (`request_url.go`), and httptest requests carry `Host: 127.0.0.1:PORT` exactly — no normalization drift; string-vs-string `Port()` comparison against the live port is sound.

**Row 4 — prototype alias 404 lock. CONFIRMED, but the mechanism as described is ambiguous.** `getJSON` (`flow_test.go:466`) never asserts status — it decodes any body. A 404 with a JSON error body decodes fine and fails only indirectly via missing fields; a non-JSON 404 fatals on decode. Either way the test fails, so the detection works, but pin the design to `assertStatus(t, ..., http.StatusOK)` **first**, then `getJSON` — the design's "getJSON/status check" hedge should be resolved. The alias route is mounted unconditionally (`server_routes.go:153` → `mountDiscovery`), so the row-4 mutation (gating the alias behind `oidcGateOn`) is a real regression class and this lock is load-bearing.

**Row 5 — C2 userinfo/end_session. CONFIRMED.** `UserInfoEndpoint`/`EndSessionEndpoint` are set under `s.oidcGateOn()` (`buildBaseMetadata:157-160`); equality on `userinfo_endpoint`/`end_session_endpoint` fails on drift or re-gating. One precision note on C1: of the 8 consts listed, `PathToken`, `PathRevoke`, `PathUserInfo` are already re-exported by `interfaces/sso` (`server_routes.go:38,47,48`) — only `PathLogin`, `PathJWKS`, `PathIntrospect`, `PathEndSession`, `PathOAuthAuthorizationServerMetadata` actually require the new `shared/core` import. C1's direction is right; the list overstates by 3.

**Row 6 — R2 non-test reintroduction. CONFIRMED, with a load-bearing pattern detail.** The quoted form `"/authenticate"` has exactly 1 hit in `cmd/` today — `scaffold_contract_test.go:136`, a `_test.go` file — and **0 non-test hits** (I verified with the quoted pattern; the unquoted form has ~30 legitimate comment/word hits like "can authenticate", "unauthenticated"). The quoted pattern is therefore mandatory, not cosmetic, and the design does pin it. **Over-broad flag:** the content-level scan also matches comments and non-route string literals — a legitimate future non-test comment naming the legacy path fails the guard. Identical posture to `assertNoLegacyPathPort` (its own comment at line 131 contains the unquoted form), so precedent-consistent; document it.

**Row 7 — exclusion removal fails on day one. CONFIRMED, non-vacuous.** Removing the `_test.go` skip exposes exactly the byte sequence at `scaffold_contract_test.go:136` → `bytes.Contains` fires → fail naming file+line. This is the strongest non-vacuity property in the whole table.

**Row 8 — R2 root resolution. CONFIRMED pattern, but the sanity count is the weakest detection in the table.** `runtime.Caller(0)` + 3×`Dir` from `cmd/sso-minimal/` = repo root (the scaffold pattern at `scaffold_build_test.go:16` uses 4× from `cmd/sso-ctl/generate` — verified; 3 is correct for the shallower package). The realistic copy-paste failure (reusing the 4-level pattern) yields root = repo *parent* → `cmd/` missing → 0 files → caught by ">0". **Flag:** a one-level-*shallow* root (`cmd/sso-minimal` itself) still visits files, passes a ">0" count, and silently narrows the guard to one of seven `cmd/` packages — the claimed "non-vacuous sanity count" does not catch wrong-but-nonempty roots. Use a floor (155 non-test `.go` files under `cmd/` today; a floor of ≥100 or asserting a sentinel like `cmd/sso-server/main.go` was visited) to make the claim true.

**Row 9 — R3 loopback/numeric/`8080`/`{port}`/variables. CONFIRMED against the post-purge spec** (only `https://{host}` + `host.default: sso.example.com`; all checks pass). The `:\d+` hole C3 closes is real (`https://{host}:{port}` has no digits in the URL). **Implementation gap:** C3's check placement is unspecified — "any `{port}`-style variable" should be pinned to *both* a URL substring check *and* a scan of all `variables` keys (a `{port}` variable declared but unreferenced in the URL, default `8080`, currently escapes every stated check). The `:\d+` letter ban also rejects a legitimate future `https://{host}:8443` — spec-mandated, not a design deviation.

**Row 10 — R3 exactly-one `https://{host}`. CONFIRMED for the removal mutation (count 0 → fail). Over-broad flag:** a legitimate future edit adding a second identical-shape production entry (different `variables` block) fails too. This is the spec's own letter (R3.3: "Exactly one entry has `url == "https://{host}"`"), so it's spec-mandated brittleness, not a design bug — but the review should record it as the one C3-strengthened check that a *legitimate* spec edit could trip.

**Row 11 — R3 restructure/`parseSpec` break. CONFIRMED.** `doc["servers"]` absent → `.([]interface{})` type-assert fails → test fatal; `parseSpec` (`main.go:126`) returns an error that the test must `t.Fatalf` on. Both paths are real. The test reuses the production parser over the embedded bytes (`docs.OpenAPISpec`), so it self-tracks spec edits — no fixture drift.

**Row 12 — R4 `git diff --exit-code docs/sdks/`. CONFIRMED as a process gate.** Verified the generator has zero `servers:` handling (`main.go` never touches the key; `base_url` is a constructor parameter, `gen_py.go:83-84`), so the spec edit cannot perturb output; `emit_test.go`/`schema_test.go` lock the emitter. Not a Go test, but correctly scoped as a migration-step gate.

**Row 13 — R4/R5 `sdk-surface check` red on unrelated drift. CONFIRMED unaffected** — `sdk_surface.py` reads operationIds; the edit touches only `servers:`.

**Accepted limitation (concatenation passes R2; R1 catches it). CONFIRMED reasoning.** `"/auth" + "enticate"` leaves no quoted literal in source → R2 passes by design; the *emitted* discovery document still contains the literal `/authenticate` string, so row-2's raw-body check and row-1's equality both fire. The design's own mechanism is strictly stronger than it claims here — the raw-body check defeats concatenation, not just "behaviorally".

## Flags summary

1. **R2 sanity count (row 8)** — partially vacuous as specified (">0" misses a wrong-but-nonempty root). Hardening: floor ≥100 files or sentinel-file visit. *The one claimed detection that doesn't fully hold.*
2. **R2 pattern (row 6)** — quoted literal is load-bearing and correct; document the comment/string-literal over-breadth (legit future comment naming the path fails).
3. **R1 port parse (row 3)** — `8080:0` = `url.Parse` *error*, not a port comparison; parse-error branch must be a `t.Fatalf`; port checks are subsumed by row-1 equality (value = diagnostics only).
4. **R1 alias lock (row 4)** — `getJSON` doesn't check status; pin `assertStatus(200)` first for a crisp failure.
5. **R1 raw-body (row 2)** — only detector for unasserted fields (concrete: `check_session_iframe`); over-broad only against policy-URI content containing `/authenticate` (low risk).
6. **R3 (rows 9–10)** — `{port}`-check placement unspecified (pin URL-substring + variables-key scan); exactly-one count is spec letter but trips on a legitimate second identical-shape entry; `:\d+` letter already bans legit explicit ports like `:8443`.
7. **C1 precision** — 3 of 8 consts already re-exported by `interfaces/sso`; only 5 need the new import (direction and conclusion unaffected).

No helper mismatch: `editionServer` (edition_test.go:112), `assertStatus` (131), `getJSON` (flow_test.go:466), `parseSpec` (main.go:126), and the `runtime.Caller` pattern (scaffold_build_test.go:16) all exist exactly where the design says and behave as the design assumes.
