**1. Issuer-is-an-identifier (C1b) — correct.** RFC 8414 §2 calls issuer an "issuer identifier" whose `.well-known` location is "derived from"; §3 derives the metadata URL by inserting the well-known string into the issuer between host and path. OIDC Discovery §4.3 treats it as the "prefix" to `/.well-known/openid-configuration`. Nothing in either spec requires serving at the issuer URL, and this server 404s at base by design (verified: `buildProbeMux` routes `/` into the `StdRouter`, which has no `/` route → `http.NotFound`).

**2. Required-vs-optional — correct as a *server-contract* checker, mislabeled as spec semantics.** Of the four "always-present" fields, `token_endpoint` (REQUIRED both specs) and `jwks_uri` (REQUIRED under the OIDC profile; OPTIONAL under bare RFC 8414) are spec-required; `revocation_endpoint` and `introspection_endpoint` are **OPTIONAL per RFC 8414 §2** yet absence is a violation — justified only because `buildBaseMetadata` always emits them. `userinfo_endpoint` (RECOMMENDED) is correctly conditional, not required. Conversely, spec-REQUIRED `issuer` and `authorization_endpoint` are never absence-checked. For foreign docs this cuts both ways: a spec-compliant foreign doc missing revocation/introspection fails the sweep; a doc missing issuer/authorization_endpoint passes silently. The design should state explicitly that the required set is the `buildBaseMetadata` always-emitted set, not an RFC set.

**3. Equality base+Path\* — correct.** `requestBaseURL` is `scheme://host[:port]` only (never path/trailing slash), all six endpoints match `base+Path*` constants, verified statically and empirically (doc equality re-asserted against a live server).

**4. Probe semantics — correct, with one caveat.** Re-probed: GET on `/token`, `/token/introspect`, `/token/revoke`, `/par`, `/device/code`, `/` → all 404, never 405 (`StdRouter` skips method-mismatched routes → `http.NotFound`; zero 405 in the SSO router path). Empty form POST retry → `/token` 401, `/introspect` 401, `/revoke` 401, `/par` 501, `/device/code` 501, `/auth/login` 415; `/userinfo` unauth GET → 401. All non-mutating. Caveat: "any non-404 proves mount" is airtight only on a stock chain — rate-limiter 429 / degradation 503 / CORS preflight 204 precede routing and would mask an unmounted path (narrow false-green window; the fetch step usually catches it).
