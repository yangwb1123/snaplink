## Verdict per validation target

**1. Per-class token bucket (≤2/s/class, burst 10, global ≤8/s) — correct and contention-safe, with two semantics that must be pinned.**
- Measured: 100k concurrent attempts → exactly 10 emitted (burst), then 2/s refill; sustained multi-class floods stayed under every cap. 82 ns/check at 10.15M checks/s single-mutex → ~8 ms CPU/s at a 100k RPS flood, negligible.
- **Gap A**: with a class-keyed shared bucket, 3×2=6/s < 8/s, so the global cap never binds (harmless safety net). If an implementer builds per-site or per-package buckets, the real budget silently doubles (up to 48/s). Pin: one shared per-process limiter keyed by class.
- **Gap B**: the limiter cannot live in `interfaces/ratelimit` — `protocols/oauth`→`interfaces` is an upward edge and `layerExemptions` is shrink-only. It must live in `oauthwire` itself (both layers import it; it already owns the class enum) or a new `shared/` package.
