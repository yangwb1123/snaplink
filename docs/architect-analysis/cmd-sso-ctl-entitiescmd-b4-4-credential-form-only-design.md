## 3. Design

### 3.1 API changes

**Wire API (breaking by design):** the **eight** RFC-mandated credential endpoints (token, introspect, revoke, par, device/code, device/verify, mfa, backchannel-authentication) reject `application/json`, missing Content-Type, and any unexpected Content-Type with their canonical 400 (`invalid_request`; `mfa_invalid` on `/auth/mfa`) before any credential logic runs. The two `/api/v1/admin/*/compromise` sites are **not** switched (reconciliation D3: non-RFC-mandated control-plane APIs with JSON-only declared contracts; the generated SDK ops stay JSON byte-identical). Form-encoded requests, including `;charset=UTF-8` parameters and empty bodies under a form Content-Type, behave exactly as today. This is the hardening the direction mandates; no config knob (per requirements §3: unconditional).

**Go API (additive):**

| Symbol | Location | Notes |
|---|---|---|
| `oauthwire.BindParamsFormOnly(ctx core.HandlerContext, v any) error` | new `protocols/oauth/oauthwire/bind_strict.go` | Form CT → `ParseForm` + `formIntoStruct`; any other/missing CT → unexported sentinel `errFormOnly`. Shares the normalized-media-type helper and form decoder with `BindParams` — one definition of form semantics |
| `oauth.BindParamsFormOnly` | `protocols/oauth/aliases.go` (var block beside `BindParams` alias) | Preserves the `oauth.*` import-path surface for the four protocol-layer sites |
| `bindOAuthParamsFormOnly(ctx HandlerContext, v any) error` | `interfaces/sso/server_jar.go` (beside `bindOAuthParams` :304) | **Four** interfaces/sso sites switch to this delegate (token, device/code, device/verify, mfa; D3); `bindOAuthParams` remains for the two admin compromise sites and non-credential dual-mode consumers |

**No new exported `Err*`** (handlers collapse every bind error to the same pre-existing 400 — oracle safety; the sentinel stays unexported, so `docs/error-codes.md` gains only a note, not a code). **No proto, no config, no store, no route changes.**

**Refactor inside `bind.go` (byte-identical):** extract the CT normalization (:31-35) into `normalizedMediaType(r)` and the form path (:38-41) into `bindForm(r, v)`; `BindParams` becomes a thin switch over the helpers. Behavior unchanged; `BindParams` complexity drops, keeping the file under the 500-line / complexity-15 budgets. `bind_strict.go` is the only consumer of `errFormOnly`.

**Form decoder extension (F1 decision, see `…-credential-form-only-decisions.md`):** `setFormField`'s `case reflect.Slice` (:128-134) gains a `reflect.Uint8` sub-branch covering `json.RawMessage` (`[]byte`): the form value is the serialized JSON text — the JSON-string form encoding of RFC 9396 §3 (`authorization_details`) and OIDC Core §5.5's URL-encoded JSON object (`claims`). Exactly one value required; `json.Valid` must pass; repeated keys or non-JSON values → bind error → the site's existing canonical 400. Bytes stored verbatim; all downstream PAR validation (`ValidateAuthorizationDetails`, `RARLimits`, allowlist; `ValidateClaimsParameter` at login) is untouched. Byte-identical for every existing supported field kind (string/bool/int/*int/[]string); the only behavior change is for form keys that today silently drop (PAR `authorization_details`/`claims`; collateral: `interfaces/admin/governance.go:61` `payload` — disclosed, additive, same defect class). `map[string]string` deliberately stays silent-skip in the shared decoder (would break admin/selfservice form consumers); MFA `params` fail-loud lives at the handler (F3).

### 3.2 Binder semantics (pinned)

- `normalizedMediaType` strips `;parameters` and lowercases — `application/x-www-form-urlencoded; charset=UTF-8` binds; `application/json; charset=utf-8` rejects. Identical parameter tolerance to today.
- Empty body + form CT: `ParseForm` succeeds on an empty body, `formIntoStruct` yields the zero struct, and per-endpoint validation runs unchanged (e.g. `/token` → 400 `invalid_request` for missing `grant_type`). The "empty body + no Content-Type is treated as JSON" default (:24-25) is dead on the credential surface.
- Error mapping at the eight strict sites: all bind errors → the site's existing 400 body. `/auth/mfa` keeps the `mfa_invalid` collapse with no audit (server_mfa.go:250-252). No error text, code, or header distinguishes `errFormOnly` from a malformed form body - the smuggling surface closes without adding an oracle.
- Ordering (unchanged): `tokenNoStoreHeaders` is stamped before parsing at every site; body parse precedes client auth on `/token` and `/token/introspect`. Under the strict binder, an unauthenticated **JSON** request now 400s at the parse stage — that is T-8(b)'s mandate and the intended precedence change; every **bindable** (form) request still reaches the 401 `invalid_client` gate (T-9 resolution, requirements §5 R4).

### 3.3 Compatibility constraints

- **Regression boundary — non-credential `BindParams` consumers are byte-identical**: all 44 sites outside the credential ten keep dual-mode JSON/form semantics: `interfaces/commerce/*` (payment_ingest JSON-required via `normalizedJSON`), `interfaces/admin/*`, `protocols/selfservice/*`, `internal/adminuser/*`. `oauthwire/bind.go`'s default branch is untouched (requirements §7 "Do not modify"). A comment in bind_strict.go points back at this boundary so no future cleanup flips the global default.
- **`/auth/login` untouched** — JSON-only (`rejectNonJSONLogin`, server_login.go:27); its test posts stay JSON.
- **CLI untouched** — admin gRPC-gateway path, never BindParams (verified §1).
- **Budgets**: `protocols/oauth/oauthwire` non-test files 6 → 7 (≤10); `interfaces/sso` stays at 60 non-test files (no new files — only the server_jar.go delegate); `bind_strict.go` ≤ 500 lines, `BindParamsFormOnly` ≤ 50 lines, complexity ≤ 15, nesting ≤ 3. No new packages, no `cmd/` imports, dependency direction unchanged.
- **SDK compatibility — deferred to the gensdk workstream (reconciliation D1/D2)**: this change does **not** touch `cmd/gensdk` or `docs/sdks/*` (generator, runtimes, emitted `client.ts`/`client.py`, `dist/`, `client.test.mjs`, READMEs). The generated SDKs' form emission for the **seven** in-surface credential ops is delivered by `docs/architect-analysis/cmd-gensdk-b4-4-credential-form-design.md`, driven by `op.ContentType` (not `tsUsesClientAuth`). Its serializer value rules (§2.2/§2.3) are the binding wire contract this change's server semantics must match: RFC 9396 §3 JSON-string single key for `claims`/`authorization_details` (F1), `params` key → `mfa_invalid` (F3), bools `"true"`/`"false"` (bind.go:116-117). The two generated admin compromise ops (`adminCompromiseCredential` client.ts:2126 / client.py:1659, `adminReportCryptoKeyCompromise` client.ts:2136 / client.py:1667) stay JSON — excluded from the strict surface (D3).
- **OpenAPI**: `application/json` requestBody variants dropped from the **eight** strict paths (the seven + `/backchannel-authentication` — D5); the two admin compromise paths are **not** touched (JSON-only, dual-mode sites — D3); the `/token` "Form + JSON" description paragraph (:1064-1066) rewritten to form-only; form schema stays (already present). Contract update lands in the same change (AGENTS.md §5.6).
- **Out-of-tree callers**: breaking — any client sending JSON or omitting Content-Type to a credential endpoint must switch to form-encoded. CHANGELOG entry required (breaking wire change, single-commit rollout, revert restores the JSON default).
