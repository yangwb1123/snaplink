## Blocking findings: NOT resolved, NOT dismissed with valid reasons

1. **Oracle leak in `authorizeGRPC` (protocol F1 High / security F1 Medium).** D1's error table promises "the status code + constant message is the whole wire signal," but D1 explicitly keeps `authorizeGRPC` "unchanged" — the branch every gRPC caller hits still embeds `ValidateToken` cause (`"invalid token: %v"`, `"scope check: %v"`), distinguishing expired vs malformed vs alg-allowlist vs length-policy. The design does not mention this branch anywhere. The protocol reviewer's bottom line names this as the single most defeating gap.
2. **D3 revoked-token semantics self-contradiction (protocol F2 / distributed D-F1 High).** D3 simultaneously claims "revoked/not-found → `Unauthenticated` (matches HTTP's contract)" and "store error → fail open," while the cited HTTP code is fail-open on `ErrTokenNotFound` (verified), and the only in-tree store (`MemoryAdminTokenStore`, per-process, wiped on restart, no bus propagation) makes the strict bullet a fleet-wide gRPC admin lockout after any restart or replica-affine call. Both bullets remain verbatim in the design; the "matches HTTP's contract" claim is factually false.
3. **D1 failure-mode table misstates rate-limit failure (distributed D-F2 High).** Design says "`rateLimitDenied` with a failing limiter returns denied (429 semantics preserved)" — unrepresentable in the SPI: `Allow(key) (bool, time.Duration)` has no error channel and `SQLiteLimiter` fails open (`true, 0`) on every SQL error (verified). The design's fail-open/fail-closed boundary — a regression boundary per AGENTS.md — is documented wrong.
4. **Quota predicate drift (protocol F3 Medium; named in their bottom line).** D1 charges gRPC by `scopeForGRPC == ScopeWrite` while HTTP charges by verb (`isAdminWriteMethod`); `PolicyService/Watch` charges on gRPC but has no HTTP route, and the `SetMethodScope` read-override POSTs charge on HTTP but would not on gRPC. Design claims "transports can never drift" while encoding a drift.
5. **Concrete-value destructive rules silently inert on gRPC (security F3 / protocol F5 Medium).** A rule `path_prefix: /api/v1/admin/tenants/tenant-123` matches HTTP resolved paths but never the canonical template `/api/v1/admin/tenants/{id}` — the confirmation guard fails open for that rule class on the automation channel. D2's dismissal ("RPC passes — same as an HTTP path that matches no rule") is wrong for this class, and its mitigation is only an optional "could warn" while D2 Failure modes states "No startup error for unmatched rules."
6. **`StreamEvents` mid-stream revocation decision (security F4/F6 Medium).** D3 documents non-teardown (bounded-writes reason) but never names the audit-forgery consequence on the one surface with type-unvalidated client events, and its "token expires mid-stream" framing is contradicted by the unconditional close-touch (`Touch` doesn't check `ExpiresAt`, verified). The security reviewer requires an explicit decision; none exists.
7. **Discovery `Register`/`Deregister` uncovered (architect F1 Medium / security F9).** Exact-match gated, `admin:write`, no annotations, no HTTP surface — D2's table and conformance test (annotation-set + prefix-family assertions) cannot see them. Unaddressed; the design's "every gated RPC is represented" claim is inaccurate.
8. **Per-replica semantics and rollout sequencing (distributed D-F3/D-F5 Medium).** Shared bucket and quota are per-process (N independent buckets; fleet aggregate N×limit) — the config-reference note must say so; and `--validate-only`'s unknown-key acceptance (executed: exit 0) means old binaries ignore `admin.grpc_tls` and keep plaintext through the mixed-version window with a green preflight. Neither appears in the design.
9. **Per-message work unbounded on streams (perf F1 Medium).** One quota unit per `StreamEvents` stream vs unbounded synchronous `Recorder.Record`+chain-hashing per message; design neither budgets per message nor quantifies/accepts the exposure.

**Net:** six independent reviews, three of which explicitly say "should not proceed" — the design was never revised in response, and none of the blocking items were dismissed with reasons that survive contact with the code I re-verified. The sound core (ordering, pre/post split, no-new-storage, D4 posture, `deps.go` relocation) stands, but the gate's own oracle-safety claim, D3's parity claim, and D1's failure-mode table are each contradicted by the executable tree.

VERDICT: FAIL - D1 oracle leak kept in `authorizeGRPC` ("invalid token: %v"/"scope check: %v") falsifies the design's oracle-safety claim; D3's strict revoked→Unauthenticated bullet contradicts HTTP's fail-open shape and breaks under restart/replica-affinity with the only in-tree MemoryAdminTokenStore; D1 failure-mode table misstates rate limiting as fail-closed when the SPI/SQLiteLimiter fail open; quota predicate drift (gRPC scope-based vs HTTP verb-based, Watch/SetMethodScope asymmetries); concrete-value destructive rules silently inert on gRPC with no mandatory startup warning; StreamEvents mid-stream revocation/audit-forgery decision and close-touch contradiction unaddressed; discovery Register/Deregister uncovered by the D2 conformance test; per-replica bucket/quota semantics and validate-only/rollout gaps undocumented
