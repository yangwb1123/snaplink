## Findings unresolved in the design (blocking)

1. **H1 — cross-tenant blast radius (security F1, QA F4).** Decision 5 cascades on `len(revoked) > 0` with no `ClientID`/tenant filter; the design is *silent* on scoping. `/token/revoke` never binds the token to the authenticating client (verified), cross-tenant exchange is live, and `ChainHop.ClientID` is recorded. Undecided High-severity security question — principal B1, needs security + maintainers.
2. **H2 — `HopsBySession` silent truncation (all 6 reviews).** The design *explicitly dismisses* the hazard with wrong reasoning: "plain indexed `... LIMIT ?` — no recursion, so no truncation hazard" (D3). The LIMIT itself is the silent cap; the D6 cascade audits success while the oldest >1000 mints survive. No truncation signal in the D1 contract; the acceptance table has no `HopsBySession` test at all (QA F1). Principal B2.
3. **M1 — false "200 written before the cascade" claim + no timing budget (protocol F6, DS F-6, security F2, QA F3, DB F-DB-3, perf P-1).** Verified: `revokeAccess` runs before `ctx.JSON(200)` at `handle_revoke.go:97-111`. D5's "written by the existing path before/independent of the cascade; runs on a side channel" is factually false. Also unresolved: the in-band cascade's cost (up to 1000 queries + 3×1000 marks + 1000 upserts + 1000 bus 2-RTT publishes ≈ 0.1–4 s) has no stated bound or off-path legs (perf P-1), and the O(1000 × deny-set size) exclusive-lock prune sweep per issuer stalls concurrent `Validate` (perf P-2). Principal B3.
4. **M2 — pre-v2 rows (protocol F5, DS F-3, security F5, QA F7, DB F-DB-6).** The `ErrHopMissingExpiry` pin is reasoned (never deny-for-zero), but the *permanence* is unaddressed: pre-upgrade roots permanently unrevocable from the admin surface; any legacy hop in a subtree 500s every cascade forever (append-only). No upgrade note in the endpoint contract/error-code entry, no skip-provably-expired refinement. Principal B5 (partial).
5. **M3 — expire-closure placement fallback infeasible (security F4, QA F6).** Design D4's fallback home `server_token_clientauth.go` is 483/500 (17 lines) — verified; a ~35-line closure cannot fit; no alternative split planned. Principal B4.
6. **M4 — bus `exp` trusted as-is (DS F-2, QA F8).** D8 defines `MetaRevokedExp` with no receiver clamp; a zero/garbage exp is pruned immediately on the peer = silent denial drop. Principal B5 (partial).
7. **M5 — introspection-cache staleness (protocol F2, QA F5, DB F-DB-11, perf P-7).** D10.11 documents the out-of-band validator residual only; the introspect path (cache hit returns before `Validate`, verified) is never declared. Principal B3 (partial).
8. **F-DB-2 — stock-wiring contradiction (DB review; post-principal).** Verified: `cmd/` imports nothing from `domains/tokenexchange`; `WithTokenExchangeChainStore` is called only in `test/` (memory store). The spec claims "stock `sso-server` admin API" while the design adds no builder/config knob — D8's restart-survival and cross-replica parity claims are unreachable in the stock binary, and the sqlite durability path has zero integration coverage. The design must choose (stock enablement vs. explicit SDK-embedding re-scope).
9. **F-DB-3 — N+1 BFS without snapshot isolation (DB review).** One `getChildren` per visited node, each a separate snapshot: a concurrent mint mid-walk escapes silently, and the full cost is in-band pre-200. The single `WITH RECURSIVE` recommendation resolves race + latency + crash atomicity together; unaddressed.
10. **QA F2 — delegation E2E harness is net-new.** Design step 7 says "Integration (`test/`, `ssotest`)" as if extendable; verified: `WithAgentDelegationGrant` appears in zero test files. The flagship Improvement-3 tripwire needs a new harness the design doesn't acknowledge. Also unaddressed: F-DB-5 (standalone busy_timeout), F-DB-9 (non-composite session index), L1 (OpenAPI enum drift), L3 (destructive-confirm gate).

## Verdict

The keystone, extension-interface approach, fail-closed discipline, and oracle body-safety are sound and source-verified — but the design carries one false factual claim, one consensus High defect it explicitly dismisses with incorrect reasoning (`HopsBySession` "no truncation hazard"), one undecided High-severity security question (blast radius), an infeasible placement fallback, and unresolved post-principal Highs (stock-wiring contradiction, snapshot-isolation race, unbounded in-band cost). The blocking amendments B1–B5 have not been applied, and three additional High/Medium findings arrived after the principal review. The design as written cannot proceed to implementation.

VERDICT: FAIL - B1 blast radius undecided (cross-tenant destruction primitive); B2 `HopsBySession` silent LIMIT-1000 truncation dismissed with wrong reasoning, no truncation signal; B3 false "200 written before cascade" claim + undeclared timing/introspection residuals + no cascade cost bound (perf P-1/P-2); B4 expire-closure fallback infeasible (17/500 lines); B5 pre-v2 permanence undocumented + bus `exp` unclamped; F-DB-2 spec/design stock-wiring contradiction; F-DB-3 N+1 walk without snapshot isolation (concurrent-mint escape); QA F2 net-new delegation harness unacknowledged.
