## Summary of decisions

**Decision 1 — Secret regeneration.** `SecretRotator` capability type-asserted from `r.Clients` (structurally satisfied by every `ClientStore` today, declared for explicitness). Rotation runs inline in the clients stage, per client, only for clients *written by this restore* whose post-write record is `Active && Secret == ""` — Merge never mutates pre-existing clients. Per-client rotation errors flow through a per-call `restoreSession` (no mutable fields on the shared `Restorer`, no `runPlan` changes), so they're non-fatal. Ordered before `InvalidateRestoredControlPlane()` so one invalidation covers rotated secrets. `RequiresRotation` counter + `CredentialRecovery{ClientID, Secret}` report field; secrets stripped from audit/operations records.

**Decision 2 — WebAuthn portability.** Capability guard lives in `domains/authenticators/webauthn` (`CredentialLister`, `HandlePreservingUserCreator`, record type) per the "guards live with implementations" rule; snapshot imports it (already imports `domains/*`). Export carries a verification-relevant projection with the bulky `Attestation` blob zeroed. Restore is insert/converge with fail-closed counter-regression skip. **No Phase B prune** — deliberate deviation from "replace wipes the category," justified by destructive-credential-removal risk and the fact that the destination is the authority on newer credentials; the orphaned-credential-on-user-recreate interaction is flagged.

**Decision 3 — TOTP seeds.** Three-gate export: explicit `IncludeCredentialSeeds` flag + real sealer + `SeedExporter`; the flag-set-with-missing-gate cases are hard errors, and the "silently absent" language is read as the flag-unset default (the only reading consistent with the acceptance check). Key separation via a new optional `PurposeSealer.DeriveSealer(purpose)` on the existing `Sealer` interface — no base-interface churn; `encryptionnone` deliberately doesn't implement it. Redaction refusal lives in `Export` (the `Redactor` interface can't return errors). Restore opt-in via `RestoreCredentialSeeds`; undecryptable envelopes conservatively flag *all* users.

**Decision 4 — Schema v3.** One bump covering both categories; v1/v2 stay readable, v3 refused by ≤v2 binaries at the version check (protects `DisallowUnknownFields`).

**Decision 5 — Same-change contract updates.** Proto fields (`credential_recovery`, `mfa_reenrollment_required`, `requires_rotation`, two request flags), error codes, `dr-framework.md` §1/§6, openapi, feature-matrix, and the audit-stripping guard.

The doc flags two interpretation points for review: the "silently absent vs. hard error" reading on missing TOTP gates, and the `Active`-gate gap (disabled clients restored secret-less stay broken when re-enabled).
