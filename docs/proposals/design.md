Design doc written to `docs/design/tokenanomaly-durable-finding-lifecycle.md`. Each decision covers API surface, storage model, failure modes, and what could break the design, all grounded in verified code (sole `FindingStore` impl, `mergeFinding` merge rules, `threataction/sqlite` peer pattern, `BuildConfigAuditStore` switch, `layerName()` rules, `migrate.Run(ctx, db, namespace, …)` signature, 60-file ceiling, auditreport classification gates).

Key design commitments, beyond the spec:

- **One correction to the decision text**: `domains/tokenanomaly/sqlite` classifies as `domains` automatically under `layerName()`'s first-segment rule (exactly like `domains/threataction/sqlite`) — no `layerName()` edit or `layerExemptions` entry needed. Flagged in the doc header so the implementation doesn't waste time on a nonexistent gate edit.
- **Single baseline migration v1** with the final schema (status/resolved/tenant columns included), since all three decisions touch the same interface and land as one change.
- **Times as unix-nanos INTEGER**, not RFC3339 TEXT or seconds — lossless `time.Time` round-trip and exact `(last_seen DESC, dedup_key ASC)` keyset ordering; second-granularity would silently break page stability.
- **Four explicit parity traps** the conformance suite must catch: zero-`FirstSeen` (naive `MIN()` pins to epoch vs Go's keep-`next` rule), severity escalation, reopen-on-resolved, and empty-tenant preservation (`COALESCE(NULLIF(...))`).
- **Reopen-on-redetect is load-bearing for multi-replica**: with process-local observations, replica A resolves rows replica B still sees; B reopens them within one sweep interval. Converges correctly, invisible to audit — but must be documented or it reads as a bug.
- **`{key}` encoding**: `DedupKey()` contains a NUL byte, so PATCH `/…/suspicious/{key}` uses `base64url(dedup_key)`; GET rows expose the raw `dedup_key` (additive) so clients can construct the path. Cursor uses base64url of a fixed-field JSON `{l, k}` — unambiguous where delimiter-joined encodings would break on NUL/colon-bearing keys.
- **Two documented contract drifts**: `total` becomes match count (not page size) and `limit<=0` no longer means "all" — called out as observable for existing consumers.
- **Keyset honesty**: a mid-walk upsert refreshing `LastSeen` past the cursor skips a row *this* walk (found next walk) — the acceptance test must either upsert older values or assert union across a re-walk; documented as a keyset property, not a bug.
- **Failure modes mapped to AGENTS.md contracts**: boot fails loud (configaudit precedent), runtime store errors fail open on the detection side, `Ping`/readyz wiring, shutdown ordering (close after recorder + sweep goroutines join), and the multi-process sqlite/NFS foot-gun with `busy_timeout`/WAL.
- **Audit split**: admin PATCH transitions audited via `SetMeta` (new event type claimed in `control_areas.go` — two gate tests enforce this); sweep auto-resolution logged/counted but not audited (bounded-cardinality rule).
- **Sequencing**: conformance suite written first, then stores, then config/composition, then handler/wrappers, then the four contract docs in the same change.
