## The 3 improvements (## headings in the spec)

1. **`RevokeDescendants` fail-closed cascade primitive** — Problem: the entire forward-walk data plane (`GetDescendants` BFS in sqlite `chain_store.go:185` / memory `chain_store.go:82`, backed by `idx_tokenexchange_chain_hops_parent`) has zero production consumers, while `chainstore.go` self-limits to "no cascade-revocation … follow-on work". Proposal: an optional `ChainRevoker` extension interface that walks descendants and marks each JTI in a deny set (fail-closed on walk/expire errors, idempotent), leaving the read-only `ChainStore` contract untouched.

2. **Admin control surface** — Problem: `HandleTokenExchangeChain` (`interfaces/admin/lifecycle.go:109`) exposes only the ancestor query; `revokeAccess` (`handle_revoke.go:152`) is per-token with no chain awareness. Proposal: `GET .../chains/:jti/descendants` (bounded) + `POST .../chains/:jti/revoke` (`admin:write`) with new audited event types, plus an opt-in chain-aware side-effect on `/token/revoke` that preserves its byte-identical 200-always oracle contract.

3. **Agent delegation joins the chain** — Problem: `agentidentity` revocation kills only the *next* mint (`agent.go:43`), minted `delegation_token`s live to TTL, and `mintDelegationToken` never records a `ChainHop` (sole `RecordExchangeHopFailOpen` call site is `tokengrant/token_exchange.go:227`); `auditDelegationMint` omits the minted jti. Proposal: `ChainHop.SessionID` field, chain recording + jti in mint audit, and a cascade step in `RevokeSession`/`RevokeAllForHuman` so human-session revocation kills already-minted agent tokens.

Each improvement carries an acceptance check (unit tests for both backends, admin handler tests in the existing `tokenexchange_chains_test.go` pattern, integration in `test/` `ssotest`, `-race`/`make ci` gates, and unwired-store byte-identical no-op regression). Docs-only change; no Go gates needed.
