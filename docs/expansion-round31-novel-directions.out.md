## 确认已理解的关键洞察

1. **方向一（AI Agent 身份）** — 从 `sso-mcp` 的"工具桥接"升级为"Agent 身份平面"：Agent 注册、委托链（delegation_token grant type）、Agent 会话、审计区分 `subject_type`。MCP 协议是先发优势，但当前只覆盖了"Agent 代表人类调 API"这一个场景。

2. **方向二（边缘身份层）** — OpenResty Lua 缓存与核心失效机制完全脱节，密钥轮换后有 1h 安全窗口、撤销无法传播。核心问题是：边缘-核心有一致性需求，但没有任何协调协议。

3. **方向三（用户生命周期状态机）** — `User` 无状态字段，全库搜 `UserStatus`/`UserState` 零命中。缺少 INVITED/SUSPENDED/INACTIVE/ARCHIVED/PURGED 的正式状态机，导致合规（GDPR 清除）、运营（MAU/DAU）、安全（离职禁用）均缺基础。

4. **方向四（跨租户 B2B 协作）** — 租户模型完全竖井式，不支持 Org A 邀请 Org B 的用户协作。缺少 ExternalUser、Invitation、Guest 生命周期、跨租户信任策略——这三个是 B2B SaaS 的硬需求，Auth0/WorkOS/Azure AD B2B 都有一等支持。

5. **方向五（韧性验证框架）** — AGENTS.md 的 fail-open/closed 矩阵是文档承诺，不是可测试契约。全库搜 `chaos`/`fault.*inject`/`TestFail` 均零命中。唯一的验证方式是手动 kill 组件——不可重复、不可自动化。

**跨方向图谱**也很有价值——方向一+四（跨租户 Agent 协作）、方向二+五（网关分区行为验证）、方向三+四（Guest 生命周期）的组合协同效应是之前没被整合过的。
