### ⚠️ 需要修正的细微差别

**方向②（开发者应用门户） vs. 之前的 "开发者门户"**：
`expansion-analysis-20260701.md` 中的方向四将 "开发者门户" 定义为 API SDK 生成 + Swagger UI + API Key 管理——用于使用该平台自身 API 的开发者。卷三的开发者门户是关于第三方 OAuth 客户端注册、应用审核流程和 secret 轮换。这些是截然不同的功能。报告应明确此区别而非声称 "无人覆盖"。

**方向③ vs. 卷一方向一**：
报告称 卷一方向⑤（连续风险引擎）已 "局部覆盖" 身份生命周期。实际重叠更大的是 卷一方向一（通用事件驱动 Webhook）和 novel-directions 方向四（通用 OAuth 生命周期事件）。卷三通过添加领域语义（生命周期的领域模型）和出站 SCIM 进行了差异化。应明确说明这两个先决条件方向是基础基础设施，而卷三在此基础上添加了领域层。

### 对阶段划分的建议思考

阶段划分总体合理，但我提出了一个调整建议：

**方向③（身份生命周期自动化）应先于方向④（Passkey 凭据治理）进入 Phase 1**——不是因为方向④不重要，而是因为方向③所构建的 `LifecycleEventBus` 也是方向④发出 `credential_used` / `credential_revoked` 审计事件和 webhook 通知的基础。如果方向③的基础设施到位，方向④可以更自然地融入。
